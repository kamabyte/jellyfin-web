# Архитектура

Документ описывает устройство приложения: взаимодействие с Jellyfin,
аутентификацию, формирование страниц и работу проигрывателя.

## Общая схема

```
Браузер ──страницы, JSON──► Laravel (Inertia) ──REST API──► Jellyfin
   │                                                           ▲
   └──────────── видеопоток, изображения, субтитры ────────────┘
```

Сервер приложения не хранит медиаданные и не проксирует видео. Его задачи —
аутентификация, получение данных из Jellyfin, их преобразование для страниц
и согласование способа воспроизведения.

## Серверная часть

### Клиент Jellyfin

Все обращения к Jellyfin выполняет класс `App\Jellyfin\Jellyfin`. Экземпляр
создаётся на каждый запрос (`AppServiceProvider`) с токеном вошедшего
пользователя и идентификатором устройства браузера.

Каждый запрос подписывается заголовком `Authorization: MediaBrowser …`
(`ClientIdentity`). Значения в заголовке кодируются (URL-encoding): название
клиента содержит кириллицу, Jellyfin декодирует их самостоятельно. Название
устройства формируется из User-Agent («Safari · macOS»), идентификатор устройства
хранится в постоянной cookie (`DeviceId`). Благодаря этому повторный вход
с того же браузера заменяет прежнюю сессию в Jellyfin, а не создаёт новую.

Ошибки Jellyfin преобразуются следующим образом:

| Ответ Jellyfin      | Результат                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------- |
| 401                 | `SessionExpired`: выход из приложения и переход на страницу входа (для JSON-запросов — ответ 401) |
| 403, 404            | стандартные HTTP-исключения и страница ошибки                                                     |
| сетевая ошибка, 5xx | `JellyfinUnavailable`: страница «Jellyfin недоступен» (503)                                       |

### Аутентификация

Собственной таблицы пользователей нет. Используется стандартный механизм Laravel
с провайдером `App\Jellyfin\SessionUserProvider`: данные пользователя (`JellyfinUser`)
хранятся в сессии, поэтому работают обычные middleware `auth` и `guest`.

Поддерживаются два способа входа:

1. **Имя и пароль** — `POST /Users/AuthenticateByName`.
2. **Quick Connect** — приложение запрашивает код, пользователь подтверждает его
   на устройстве, где вход уже выполнен; страница входа периодически проверяет
   статус. Секрет запроса хранится только в сессии.

Кроме того, вошедший пользователь может подтвердить код другого устройства
на странице «Подключить устройство».

### Формирование страниц

Контроллеры получают данные Jellyfin в исходном виде (PascalCase), а ресурсы
`app/Http/Resources` (`ItemCard`, `ItemDetail`, `EpisodeCard`, `LibraryCard`)
приводят их к виду, удобному для интерфейса. Ссылки на изображения указывают
на публичный адрес Jellyfin (`App\Jellyfin\Image`).

Медиатеки отображаются в зависимости от типа (`LibraryKind`):

| Тип медиатеки Jellyfin                          | Отображение                              |
| ----------------------------------------------- | ---------------------------------------- |
| Фильмы, сериалы                                 | сетка постеров по всей глубине медиатеки |
| Смешанное содержимое, домашнее видео, коллекции | просмотр по папкам                       |
| Музыка, ТВ, книги, плейлисты                    | ссылка во встроенный клиент Jellyfin     |

Постраничная выдача `/Items` оформлена как стандартный пагинатор Laravel
(`ItemPage`), что позволяет использовать `Inertia::scroll()` и бесконечную прокрутку.

## Проигрыватель

### Выбор способа воспроизведения

Способ воспроизведения определяется при открытии видео и при каждой смене дорожки:

1. Браузер определяет поддерживаемые кодеки и контейнеры
   (`resources/js/lib/capabilities.ts`).
2. Проигрыватель отправляет их в `POST /watch/{id}/playback`.
3. Сервер строит профиль устройства (`DeviceProfile`) и запрашивает
   `/Items/{id}/PlaybackInfo`.
4. Ответ преобразуется в описание потока (`PlaybackSource`): адрес, способ
   воспроизведения, звуковые дорожки и субтитры.

Профиль устройства составлен так, чтобы минимизировать перекодирование:

- совместимый файл воспроизводится напрямую (`/Videos/{id}/stream?static=true`);
- при несовместимом контейнере или звуке выполняется перепаковка в HLS:
  кодеки HEVC и AV1 стоят первыми в профиле перекодирования, поэтому Jellyfin
  копирует видеопоток без изменений, а при необходимости перекодирует только звук;
- перекодирование видео происходит лишь тогда, когда браузер не может
  декодировать его сам (например, Dolby Vision без совместимого слоя вне Safari).

### Дорожки и субтитры

- Браузеры, кроме Safari, воспроизводят из файла только звуковую дорожку
  по умолчанию. Для них профиль содержит условие `IsSecondaryAudio = false`,
  и при выборе другой дорожки Jellyfin выполняет перепаковку с нужной дорожкой.
  Safari переключает дорожки внутри файла без запроса нового потока.
- Запрос к `PlaybackInfo` всегда содержит `MediaSourceId`: без него Jellyfin
  не применяет выбранные звуковую дорожку и субтитры.
- Текстовые субтитры загружаются в формате WebVTT и отображаются проигрывателем.
  Субтитры в виде изображений (PGS, VobSub) можно только вшить в видео,
  что требует перекодирования; они включаются лишь по явному выбору пользователя.
- При смене дорожки текущий кадр сохраняется на экране, элементы управления
  остаются доступны, а новый поток подключается после готовности.

### Отчёты о просмотре

Проигрыватель сообщает серверу о начале воспроизведения, позиции (каждые
10 секунд, при паузе и перемотке) и остановке (`POST /playback/{start|progress|stop}`).
На основе этих отчётов Jellyfin ведёт раздел «Продолжить просмотр», отмечает
просмотренное и завершает перекодирование после закрытия проигрывателя.
Отчёт об остановке отправляется с `keepalive` и доходит даже при закрытии вкладки.

## Структура каталогов

| Каталог                                  | Содержимое                                                           |
| ---------------------------------------- | -------------------------------------------------------------------- |
| `app/Jellyfin`                           | клиент Jellyfin, аутентификация, профиль устройства, описание потока |
| `app/Http/Controllers`                   | контроллеры страниц и JSON-запросов проигрывателя                    |
| `app/Http/Resources`                     | преобразование данных Jellyfin для страниц                           |
| `resources/js/pages`                     | страницы Inertia                                                     |
| `resources/js/components`                | компоненты интерфейса, проигрыватель (`player.tsx`, `player/`)       |
| `resources/js/lib`, `resources/js/hooks` | вспомогательные функции и хуки                                       |
| `tests/Feature`                          | функциональные тесты с подменой ответов Jellyfin                     |
| `deploy/dokploy`                         | стек Dokploy и скрипт выкатки                                        |
